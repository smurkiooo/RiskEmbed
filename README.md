# RiskEmbeddings: ML и DL на AmEx

Проект сравнивает LightGBM и Transformer для прогнозирования дефолта по ежемесячным
выпискам. Проверяем, улучшают ли эмбеддинги результат бустинга на агрегатах.

В наборе American Express Default Prediction 458 913 клиентов,
5 531 451 выписка, 188 признаков. Проверка локального parquet и сравнение альтернатив описаны
в [docs/DATASET.md](docs/DATASET.md).

## Модели и анализ

- Подготовка данных в DuckDB: обработка пропусков и агрегаты истории клиента.
- Причинный Transformer на PyTorch с предобучением CoLES/InfoNCE и регуляризацией VICReg.
- Обучение Transformer по меткам с нуля и после CoLES; выбор checkpoint по valid.
- Сравнение LightGBM на агрегатах, эмбеддингах и их сочетании; абляции времени и VICReg.
- Остаточные эмбеддинги, SHAP и пробы: какую информацию энкодер извлёк из истории.
- Разбиение по клиентам, метрики AmEx и Gini, парные bootstrap-интервалы прироста.
- Один Airflow DAG для воспроизводимого эксперимента, с теми же шагами, что в локальном CLI.

## Запуск

```bash
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python -e ".[dev]"
.venv/bin/python -m pytest
.venv/bin/python scripts/run_experiment.py --quick --force
```

Перед экспериментом положите `train.parquet` и `train_labels.csv` в `data/raw/amex/`.
Данные в репозиторий не включаются. Полный запуск, требования и Airflow:
[docs/SETUP.md](docs/SETUP.md).

## Протокол и ограничения

Train/valid/test разделены по клиентам примерно 60/20/20. Квантили, категории,
предобучение и остаточная проекция обучаются только на train. Early stopping использует valid.
Локальный test: отдельные клиенты официальной обучающей выборки; это не OOT.
Усечение истории выписок проверяет чувствительность к её длине. Для временной валидации нужен другой период.

Отрицательный класс в исходном соревновании прорежен: необработанные вероятности моделей
не интерпретируются как банковская PD. Основной результат: сравнение ранжирования.

Полные результаты, кривые обучения DL и устройство проекта описаны в
[project_overview.html](project_overview.html). Страница создаётся автоматически из результатов
эксперимента и работает без интернета. Таблицы: [reports/EXPERIMENT.md](reports/EXPERIMENT.md).
`--quick` служит проверкой работоспособности и сохраняет отдельные результаты.

Подробно о проверках и их границах: [аудит утечек](docs/LEAKAGE_AUDIT.md).

## Структура

```text
configs/default.yaml      параметры AmEx и моделей
src/riskembed/            данные, Transformer, предобучение, признаки и метрики
scripts/                 проверка → подготовка → обучение → анализ → отчёт
dags/amex_experiment.py   один DAG без ежедневного скоринга
reports/                 аудит источника и результаты экспериментов
tests/                   небольшие искусственные примеры; реальные данные не требуются
```

Проект ограничен сравнением ML/DL на реальных данных. Генератора синтетики,
survival-задачи, ежедневного скоринга, feature store и реестра версий в нём нет.
