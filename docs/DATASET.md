## Границы проверки

Подтверждены структура, объём, покрытие меток, даты, длины историй и отсутствие дублей.
В наборе нет отдельной колонки target среди признаков; допустимые имена признаков проверяются.
Это не доказательство отсутствия любой семантической утечки внутри анонимизированных признаков.

Эквивалентность каждого значения официальному CSV не проверена: оригинального CSV
в проекте нет. Parquet задаёт формат хранения. Integer-кодирование, замена пропусков и перевод
в float32 меняют представление значений. Их нельзя автоматически считать побитово обратимыми.
Текущий адаптер рассчитан на integer-сборку: `-1` в integer-признаках трактуется как пропуск,
`D_63` и `D_64` уже закодированы целыми числами. Произвольный другой parquet может потребовать
другого адаптера. Полный текст карточки raddar при проверке был недоступен. Детали преобразований
по документации автора независимо не подтверждены.

## Ограничения исходной задачи

[Организатор](https://www.kaggle.com/competitions/amex-default-prediction/data) описывает
ежемесячные агрегированные клиентские профили и одну метку дефолта по будущему окну наблюдения.
Это не сырые транзакции и не набор с точными датами дефолта для survival-модели.
Метка не переопределяется как PD-12 из удалённого синтетического эксперимента.

Отрицательный класс прорежен до 5%; в
[официальной метрике](https://www.kaggle.com/competitions/amex-default-prediction/overview)
ему назначен вес 20. Доля дефолтов 25.9% относится к выборке, а не банковскому портфелю.
Без коррекции и проверки калибровки выход модели нельзя выдавать за банковскую PD.

Официальный test не имеет публичных меток в скачанных файлах. Поэтому для локального
сравнения используется клиентский holdout внутри официального train. Последняя дата у всех
в одном месяце: полноценный OOT из этого источника не получается. Усечённая история
проверяет лишь чувствительность к доступному объёму истории.

## Альтернативные датасеты

| Вариант | Преимущество | Ограничение | Решение для этого проекта |
|---|---|---|---|
| Текущий AmEx integer parquet | Полный объём, уже подготовлен, достаточно данных для DL | Сторонние преобразования, нет локального размеченного OOT | Оставить основным |
| Официальный AmEx CSV → собственный parquet | Проверяемая цепочка преобразований от первоисточника | Больше скачивание и подготовка; задача и split не улучшаются | Лучшее усиление происхождения данных при необходимости |
| MBD-mini | Реальные последовательности транзакций и временные задачи | Цель — покупка банковских продуктов, а не дефолт; нужен другой проектный вопрос | Выбрать при смене задачи на поведение/рекомендации |
| UCI Default of Credit Card Clients | Маленький и простой, 30 000 клиентов, 23 признака | Меньше данных и короче история для демонстрации sequence DL | Подходит для учебного примера, менее подходящая основа здесь |

Источники альтернатив:
[официальный AmEx](https://www.kaggle.com/competitions/amex-default-prediction/data),
[карточка MBD и MBD-mini от авторов](https://huggingface.co/datasets/ai-lab/MBD),
[статья MBD](https://arxiv.org/abs/2409.17587),
[карточка UCI](https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients).

Для проекта по кредитному риску подходит текущий AmEx.
Переход на MBD-mini даст более богатую событийную задачу, но изменит предмет исследования.
Маленький размер parquet сам по себе не требует замены источника.
Для строгой проверки точности значений следующим шагом будет сравнение с официальным CSV
по ключу `(customer_ID, S_2)` и документирование преобразований; такой сверки здесь не было.
